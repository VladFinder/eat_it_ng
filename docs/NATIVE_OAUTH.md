# Вход через Google в установленном Android-приложении

Исправление доставляется через OTA в APK с runtime `2.0.2` и `2.0.3`.
Нативные зависимости, AndroidManifest и ключи доверия не меняются.

## Поведение

1. Homie создаёт временный запрос на вход и сохраняет секрет подтверждения
   только в sessionStorage своего WebView.
2. Браузер открывает Google OAuth с отдельным одноразовым билетом запуска.
   Прежние проверки state и PKCE Google сохраняются.
3. После успешного Google-входа браузер показывает «Вход выполнен» и предложение
   вернуться в Homie. Сессия браузера не используется как сессия приложения.
4. Приложение получает результат по защищённому запросу, сохраняет свой bearer
   token существующим способом и загружает данные пользователя.

В этой OTA-версии пользователь переключается обратно в Homie вручную.
Автоматический возврат через Android intent/deep link потребует нативной настройки
и нового APK. При отказе Google или отмене в Homie можно начать вход заново.

## Безопасность и ограничения

- Секрет подтверждения не передаётся в ссылке; сервер хранит только SHA-256 challenge.
- Билет браузера используется один раз и связывается с провайдером и OAuth state.
- Результат можно получить только с исходным секретом и только один раз.
- Подтверждённая сервером личность Google используется для создания сессии;
  клиент не может подставить user ID или email.
- Временные запросы живут до 10 минут. В одном API-процессе их не более 1024.
  После перезапуска API незавершённый вход нужно повторить. Для нескольких
  API-процессов потребуется общее хранилище временных запросов.
- Ответы не кэшируются, проверяется Origin, создание запросов и опрос ограничены.
- Обычный вход на сайте продолжает использовать HttpOnly cookie и веб-редирект.

## Публикация

Сначала обновить API и проверить healthcheck. Затем опубликовать OTA для текущего
runtime стандартной командой из LIVE_UPDATES.md.

Для APK `2.0.2` собрать тот же веб-код в отдельном worktree, восстановив только
нативную оболочку и ota-trust.json из её релизного коммита
`4143dc0f70d2f5c86c31183af972677e79aa8b41`. Использовать те же node_modules:
нативные зависимости в этом исправлении не менялись. Проверка nativeFingerprint
в ota:publish должна проходить; обходить или отключать её нельзя.

Рабочую копию автодеплоя и её нативную конфигурацию для совместимой сборки не менять.
Пакеты разных runtime находятся в разных каталогах /updates/ и не заменяют друг друга.

## Проверка на устройстве

Полностью закрыть Homie, открыть с интернетом и дождаться OTA. Нажать
«Продолжить с Google», завершить вход в браузере, вернуться в Homie. Должен
открыться аккаунт выбранного пользователя. Повторно регистрироваться не нужно.
Также проверить отмену Google, отмену в Homie и временное отсутствие сети.
