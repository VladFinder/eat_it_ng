# Подключение homie-web.app

Новый публичный адрес: `https://homie-web.app`. Эта инструкция предполагает
подключение к текущему серверу приложения. Используются существующие API,
пользователи и база `/opt/eat-it/app/data/eat-it.db`.

## 1. DNS

У регистратора создать A-запись для `@` на публичный IPv4 сервера приложения.
На момент подготовки инструкции `eat-it.space` указывает на `31.129.106.119`;
перед изменением проверить адрес в панели VPS. `homie-web.app` пока указывает
на `5.101.153.40`.

Если IPv6 на VPS не настроен, удалить постороннюю AAAA-запись нового домена.
Новый конфиг обслуживает только `homie-web.app`; `www` подключать отдельно при
необходимости, с DNS-записью и сертификатом.

```bash
dig +short homie-web.app A
dig +short homie-web.app AAAA
```

Зона `.app` требует HTTPS в браузерах:
[требование Google Registry](https://www.registry.google/domains/app/).

## 2. Nginx и HTTPS

После доставки этого изменения в `/opt/eat-it/app` добавить отдельный сайт:

```bash
sudo cp /opt/eat-it/app/deploy/nginx-homie-web.app.conf /etc/nginx/sites-available/homie-web.app
sudo ln -sfn /etc/nginx/sites-available/homie-web.app /etc/nginx/sites-enabled/homie-web.app
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d homie-web.app --redirect
curl --fail https://homie-web.app/api/health
```

Для HTTP-проверки сертификата DNS должен указывать на этот сервер, а порт 80
быть доступен извне. После выпуска сертификата проверить его автопродление:

```bash
sudo certbot renew --dry-run
```

Существующий сайт `eat-it.space` оставить работающим: опубликованные APK могут
продолжать обращаться к `https://eat-it.space/api`. API старого домена должен
проксировать запросы на тот же процесс, без перенаправления на другой домен.

## 3. Авторизация и адрес приложения

В Google OAuth добавить разрешённый redirect URI:

```text
https://homie-web.app/api/auth/google/callback
```

Для включённого Sign in with Apple добавить новый домен и Return URL:

```text
https://homie-web.app/api/auth/apple/callback
```

Обновить разрешённые домены и сведения о сайте в настройках OAuth-провайдеров,
если они используются. Старые redirect URI пока сохранить. Провести перенос
в короткое окно: уже начатый вход OAuth на старом домене может потребовать повтора
на новом, поскольку cookies принадлежат домену, на котором начат вход.

В `/opt/eat-it/app/.env` установить:

```dotenv
APP_URL="https://homie-web.app"
```

`EnvironmentFile` переопределяет значение из systemd unit, поэтому существующий
`APP_URL` в `.env` нужно обновить явно. Затем перезапустить API:

```bash
sudo systemctl restart eat-it-api
curl --fail https://homie-web.app/api/health
```

Если устанавливается обновлённый unit из репозитория, после его копирования
выполнить `sudo systemctl daemon-reload` перед рестартом.

На новом домене браузер потребует повторный вход. Пароль, профиль, рецепты и
остальные данные остаются в существующей базе. Разрешённые origin для запросов
на запись определяются через `APP_URL`: старую веб-версию после переключения
направить на новый сайт. На старом HTTPS-сайте перенаправление добавить только
для веб-страниц, сохранив существующий `/api/` proxy и сертификат:

```nginx
location / {
    return 302 https://homie-web.app$request_uri;
}
```

Проверить, что более специфичные location для статики в старом конфиге не мешают
перенаправлению. После проверки переноса временный 302 можно заменить на 301.

## 4. Android и публикация

Нативный API в новых сборках: `https://homie-web.app/api`. Собирать и распространять
новый APK после проверки HTTPS и авторизации на новом домене:

```bash
npm run android:apk
```

При push в GitHub CI собирает debug APK; push в `main` также запускает деплой.
Автодеплой не устанавливает Nginx-конфиг и не меняет серверный `.env`.
Package ID `space.eatit.app` сохраняется, чтобы сборка обновляла прежнее приложение.

В Google Play обновить адрес сайта, политику конфиденциальности и страницу удаления:

- `https://homie-web.app/privacy.html`
- `https://homie-web.app/delete-account.html`

Текущий VAPID contact `mailto:support@eat-it.space` можно сохранить, пока этот
контакт доступен. При замене контакта сохранить существующую пару VAPID-ключей.
На новом веб-домене пользователям нужно снова разрешить уведомления: подписки
старого origin автоматически не переносятся.

## 5. Проверка и откат

Проверить на новом домене вход по паролю и включённым OAuth-провайдерам,
загрузку рецептов, добавление покупки, страницы политики и удаления аккаунта.
Проверить старый APK через старый API и новый APK через новый API.

Если перенос нужно откатить, вернуть `APP_URL="https://eat-it.space"` в серверном
`.env`, убрать перенаправление старых веб-страниц и перезапустить API. Для клиентов
с новым APK сохранить рабочий HTTPS proxy нового домена. Базу при смене домена
не пересоздавать и seed на production не запускать.
