# Добавление товаров по штрихкоду

Версия Android 2.0.4, код 6, runtime OTA 2.0.4. Минимальная версия Android — 7.0/API 24.

В «Запасах» и «Покупках» есть действие «Добавить по штрихкоду». Пользователь сканирует
код или вводит его цифрами, проверяет название, выбирает раздел, количество и место
добавления. Срок годности конкретной упаковки указывается отдельно; дата из базы
товаров не подставляется. Неизвестный товар можно добавить вручную.

## Сканирование

Android использует @capacitor-mlkit/barcode-scanning 7.5.0 и готовый интерфейс Google
Code Scanner. Требуются Google Play Services; модуль может загрузиться при первом
использовании. В манифесте объявлены необязательное оборудование камеры и barcode_ui.
Разрешение CAMERA самому Homie не требуется: Google scan() работает через интерфейс
Play Services. Для будущего перехода на собственный нативный startScan потребуются
CAMERA в манифесте и новый APK. При отсутствии модуля/сервисов остаётся ввод номера.

На сайте камера включается через getUserMedia по кнопке, без микрофона. ZXing
загружается отдельным модулем при первом сканировании; поддерживаются EAN-8,
EAN-13, UPC-A и ITF/GTIN-14. Нужен HTTPS (либо localhost для разработки).
После распознавания, закрытия окна, ухода со страницы или скрытия вкладки поток
останавливается. Поздно выданное разрешение не оставляет камеру включённой.
Кадры не отправляются на сервер. Фото, QR-ссылки и коды маркировки не обрабатываются
как товары в этой версии.

## Данные и API

- GET /api/barcodes/:code требует действующую сессию, проверяет длину и контрольную
  цифру GTIN. Канонический код — 14 цифр с ведущими нулями; UPC/EAN-эквиваленты
  считаются одним товаром.
- Сначала ищется подтверждённое название в текущем доме. Иначе выполняется запрос
  к фиксированному HTTPS-адресу Open Food Facts, без данных пользователя и авторизации.
- Публичный ответ ограничен 64 КБ и таймаутом 7 секунд. Положительный кэш — сутки,
  отрицательный — час, не более 512 записей в одном API-процессе. Одинаковые запросы
  объединяются; провайдер получает не более 12 запросов в минуту из процесса.
  При масштабировании на несколько процессов нужен общий лимит на исходящий IP.
- Отсутствие товара и недоступность провайдера различаются; оба случая допускают
  ручной ввод. Клиент не должен повторять поиск на каждый введённый символ.
- POST /api/fridge и POST /api/shopping принимают необязательный barcode.
  В одной транзакции создаётся позиция и обновляется HouseholdBarcodeProduct
  (название, единица и раздел). Названия не публикуются в общую базу и не уходят
  в Open Food Facts. Они доступны только участникам соответствующего дома.
- Сами позиции запасов и покупок сохраняют прежний формат. Старые приложения
  продолжают работать. Удаление дома каскадно удаляет его соответствия штрихкодов.
- Миграция: prisma/migrations/20261030080000_household_barcodes/migration.sql.
  Для существующих баз, обслуживаемых ensureDatabaseSchema, тот же столбцовый
  состав и уникальный индекс создаются идемпотентно при старте API.

Внешние данные: [Open Food Facts](https://world.openfoodfacts.org),
[документация API](https://openfoodfacts.github.io/documentation/docs/Product-Opener/v3/products/get-api-v3-product-code/),
[условия повторного использования ODbL](https://world.openfoodfacts.org/data).
Атрибуция отображается при получении товара из Open Food Facts. Покрытие базы
не гарантируется: перед подтверждением пользователь может исправить название.

## Проверка на сайте и устройстве

1. Войти на https://homie-web.app, открыть добавление по штрихкоду в покупках.
2. Разрешить камеру, отсканировать EAN с упаковки. Проверить остановку камеры
   после чтения, изменение названия и добавление ровно одной позиции.
3. Повторить код: должно вернуться подтверждённое название вашего дома.
4. Проверить ввод цифрами, неверную контрольную цифру, неизвестный товар,
   недоступную камеру, запрет разрешения и временное отсутствие сети.
5. В запасах явно указать дату с упаковки или «Без срока». Убедиться, что покупки
   не получают выдуманный срок годности.
6. Закрыть сканер во время запроса камеры и переключить вкладку: индикатор камеры
   должен погаснуть; старый результат поиска не должен заменить новый код.
7. На Android проверить установку модуля, отмену системного сканирования,
   повторное сканирование, обновление с 2.0.3 и вход через Google.

Нативная часть требует нового AAB. OTA для runtime 2.0.4 совместим только с новой
оболочкой. Каналы 2.0.2 и 2.0.3 не получают этот нативный модуль через OTA.
